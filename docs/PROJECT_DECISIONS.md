# MeetPoint 프로젝트 세부 결정 사항

작성일: 2026-10-07 / 작성: 서하늘(Codex 보조)

기획서의 목표와 실제 코드를 구분하여 개발 결정안을 정리한다. 역할 분담, 협업 방식과 개발 순서는 제안안이며 팀 합의 후 확정한다.

## 1. 범위와 화면

대상은 수도권에서 서로 다른 출발지·교통수단으로 모이는 20~30대 대학생·직장인이다. 핵심 가치는 실제 예상 이동시간을 비교하여 특정 참가자에게 부담이 집중되지 않는 지역과 장소를 선택하는 것이다.

**1차 MVP: F01~F06 / S01~S05.** 로그인 없이 대표자 한 명이 참가자를 입력하고 현재 기기에 저장한다. 초대 동시 참여, 투표, 계정 이력과 알림은 2차 확장이다. PWA 설치는 기본 흐름 완성 후 추가한다.

| 화면 | 흐름 | 담당 제안 |
| --- | --- | --- |
| S01 시작/입력 | 모임명·시각·참가자·출발지·수단, 추가/삭제, 저장된 약속 진입 | 서하늘 UI / 조준영 주소 검색 |
| S02 지역 비교 | 참가자 시간과 최대·차이·평균, 후보 선택 | 서하늘 UI / 조준영 계산·경로 |
| S03 장소 목록 | 식당·카페 검색과 필터, 빈 결과, 다른 지역 선택 | 서하늘 UI / 조준영 장소 API |
| S04 상세 | 주소·지도·제공 가능한 운영정보, 목적지 기준 시간 재조회 | 서하늘 UI / 조준영 데이터 |
| S05 확정/관리 | 기기 내 저장·재조회·복사·수정 | 서하늘 / 서버 확장은 오윤식 |

## 2. 기술과 환경

- 기존 Next.js 14.2.15 App Router, React 18.3.1, TypeScript 5.5.4를 유지한다. 화면과 API Route Handler를 한 저장소에서 개발한다.
- `npm ci`로 lockfile에 맞춰 설치한다. ESLint·타입 검사·빌드를 병합 전 기준으로 사용한다.
- Prisma 7.10.0·SQLite는 로컬 개발용 기반이다. User 모델은 있으나 회원가입은 미완성이다.
- 1차 약속 저장은 브라우저 `localStorage`로 설계한다. 공동 참여와 계정 동기화는 서버 모델/인증을 별도로 설계한다.
- 지도·주소·장소·경로 API 공급자는 **미확정**이다. 교통수단 지원, 비용/호출 제한, 좌표, 약속 시각 지정 가능 여부를 비교하고 연동 실험 후 확정한다.
- API 비밀 키는 서버 환경 변수에만 둔다. 지도 SDK 공개 키는 도메인을 제한한다. 실제 비밀값을 `.env.example`에 넣지 않는다.
- 배포 환경과 서버 DB는 외부 API/저장 방식 검증 후 결정한다. 로컬 SQLite 설정을 서비스 배포 완료로 표시하지 않는다.

## 3. 입력과 데이터 계약

최소 2명의 이름, 검색 결과로 선택한 출발지 좌표, 교통수단을 갖춘 뒤 추천을 실행한다. 모임은 날짜와 시각을 함께 입력한다. 좌표는 WGS84 위도/경도로, 내부 시간은 분 단위로 통일한다.

| 데이터 | 최소 필드 / 규칙 |
| --- | --- |
| 모임 | id, 모임명, 약속 시각, 참가자 목록, 확정 상태 |
| 참가자 | id, 이름, 출발지 표시명, 위도/경도, transit/car/walk |
| 경로 결과 | 참가자 id, 후보 id, 시간, 조회 시각, 성공/실패 상태 |
| 지역 후보 | id, 지역명, 좌표, 참가자별 경로, 평균/최대/차이 |
| 장소 | 제공자 id, 이름, 분류, 주소, 좌표, 제공 가능한 상세 정보 |
| 저장된 약속 | 버전, 모임 정보, 최종 장소, 경로 결과, 저장 시각 |

제공자 응답은 서버에서 위 구조로 변환한다. 위 표는 팀 내부 제안이며 외부 API의 실제 명세가 아니다. 공급자 선택 후 API URL·요청/응답·오류 계약을 합의한다.

## 4. 추천과 실패 처리

1. 수도권 주요 역/교통 거점과 참가자 분포로 후보를 만든다. 좌표 중심은 후보 탐색의 출발점으로만 사용한다.
2. 참가자별 출발지와 교통수단으로 후보까지 실제 경로 시간을 조회한다.
3. 모든 참가자의 경로가 성공한 후보만 비교한다.
4. **최대 이동시간 → 시간 차이 → 평균 이동시간**이 작은 순으로 정렬한다. 모두 같으면 후보 id로 순서를 고정한다.
5. 지역에서 장소를 찾은 뒤 실제 장소 좌표까지 시간을 재조회하고 확정을 허용한다.

평균=시간 합/인원, 최대=가장 긴 시간, 차이=가장 긴 시간-가장 짧은 시간. 정렬에는 반올림 전 값을 쓰고 화면 평균만 반올림한다. 기획서의 `[42, 36, 18, 29]` 예시는 평균 31분, 최대 42분, 차이 24분이다.

조회 실패를 0분으로 처리하거나 참가자를 제외하지 않는다. 계산 불가 사유와 재시도를 제공한다. 조회 중 중복 요청과 확정을 막는다. 약속 시각을 지원하지 않는 API는 조회 기준 시각을 표시한다. 후보 수·호출 제한·캐시는 API 실험 후 정한다.

## 5. 저장과 변경

- `localStorage`는 같은 브라우저/기기에서만 조회되며 계정 간 동기화가 아니다.
- 저장 실패·손상 데이터·저장된 약속이 없는 상태를 처리한다.
- 장소·모임명·시각을 텍스트로 복사한다. 앱 URL 복사를 공동 참여 기능으로 표시하지 않는다.
- 출발지·교통수단·시각 변경 시 확정을 해제하고 재계산한다.
- 2차 투표는 1인 1표, 동률은 생성자가 이동시간을 참고해 결정한다. 후보/출발 정보 변경 시 이전 투표를 초기화한다.

## 6. 개발 순서와 완료 기준

| 단계 | 완료 기준 | 담당 제안 |
| --- | --- | --- |
| 베이스 | clean clone, 설치, 환경 예제, 정적 검사·빌드·데모 실행 | 오윤식 관리 / 전원 재현 |
| 입력·추천 | 2명 이상, 실제 수단별 경로, 3개 지표, 실패 처리 | 조준영 데이터 / 서하늘 UI |
| 장소·확정 | 검색·상세·재계산·저장·복사·재조회 | 조준영 API / 서하늘 흐름 |
| 확장 | 설치·초대·투표·계정/알림을 필요 순서로 구현 | 오윤식 서버 / 전원 연동 |

모바일 테스트와 API 계약 검토는 공동 책임이다. 매주 수요일 수업 시작 전 push·리뷰·병합·README 이력 갱신을 수행한다. 최종 마감과 상세 주차 일정은 수업 일정과 API 검증 결과에 따라 팀이 확정한다.
